# TerrainGen

A procedural terrain and biome generator written in C++, using Perlin and fractal noise and a five parameter biome classification system inspired by Minecraft's terrain generation system, rendered in an OpenGL window.

## Overview

TerrainGen generates a 2D biome map from scratch (no external noise or terrain libraries) using a custom Perlin noise function and fractal (fractal Brownian motion) noise built on top of it. The generator uses five independent noise parameters (continentalness, erosion, weirdness, temperature, humidity), inspired by the Overworld generation system used in modern Minecraft, to classify each point on the map into one of 32 different biomes. The result is rendered in an OpenGL window with mouse controlled pan and zoom.

### Features

- Perlin noise and fractal Brownian motion (fBm) noise
- Five parameter biome classification: continentalness (ocean/coast/inland tiers), erosion (mountain vs. flat terrain), weirdness/PV (rivers, peaks vs. valleys), temperature, and humidity
- 32 biomes including ocean temperature variants (cold, lukewarm, warm, and their deep variants), mountain variants (windswept hills, mountain, jagged/frozen/stony peaks), and climate based land biomes (desert, savanna, forest variants, jungle variants, swamp variants, taiga variants, tundra, badlands, etc)
- Rivers generated from a peaks and valleys (PV) noise derivation, carved through non-mountainous terrain (based on how Minecraft generates rivers)
- OpenGL rendering pipeline (GLFW, GLAD, and shaders) with a texture created from the generated biome data
- Mouse scroll-to-zoom and click-and-drag panning, clamped to the generated map bounds
- PPM image export as a way to save your generated maps, named "Map_[SeedUsed].ppm" so you can get the seed as well. (The seed is also printed to the console)

## Dependencies

- **C++17** compiler (developed and tested with MinGW-w64 / GCC via MSYS2 UCRT64)
- **CMake** (3.10+)
- **Ninja** (or another CMake-supported generator)
- **GLFW3** windowing and input
- **GLAD** OpenGL function loader (pre-generated sources are bundled in `external/glad/`)
- **OpenGL** 3.3 (Core Profile), provided by the system's `opengl32` on Windows

## Building (Windows, MSYS2)

1. Install [MSYS2](https://www.msys2.org).
2. Open the **UCRT64** MSYS2 terminal (not the default MSYS2 shell) and install the toolchain:
   ```
   pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja mingw-w64-ucrt-x86_64-glfw
   ```
3. Make sure `C:\msys64\ucrt64\bin` is on your Windows `PATH`:
    ```
    [Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\msys64\ucrt64\bin", "User")
    ```
    `Restart terminal`

4. From the project root:
   ```
   cmake -B build -G Ninja
   cmake --build build
   ```
5. Run the resulting executable:
   ```
   ./build/TerrainGen.exe
   ```

> GLAD's generated loader files are already included under `external/glad/`, so no separate GLAD setup step is needed.

## Design Notes

- Generation and rendering are fully independent. `TerrainMap` has no knowledge of OpenGL, textures, or windows, it produces plain biome/parameter data that can be consumed by the OpenGL renderer, the PPM exporter, or any future renderer without modification.

- Biome classification mirrors Minecraft's real Overworld system in structure. Continentalness and erosion decide the large-scale terrain shape (ocean vs. land, flat vs. mountainous) before climate (temperature/humidity) ever gets used for the specific biome flavor within that shape.

- Noise is reused using coordinate offsetting. Several parameters that are related but need to vary independently (river carving weirdness vs. mountain-shape weirdness, or land temperature vs. broad ocean temperature) are sampled from the same underlying noise generator at different coordinate offsets or octave counts, rather than creating an entirely separate `NoiseGenerator` instance for each, this keeps memory/setup cost down while still producing visually distinct fields.

## Known Limitations / Future Work

- The map is generated once at a fixed size; there is no chunked or infinite-world generation.

- No 3D terrain mesh/height rendering. The current renderer displays a flat, color-coded biome map. A height-based 3D or orthographic renderer was intended originally but was not implemented due to the project deadline. This will most likely be implemented in the near future.

- Small, fully surrounded bodies of water (lakes, but techincally ocean biome) can occasionally show more than one ocean temperature variant, since ocean temperature is sampled from a smoothed, low-frequency noise field that isn't guaranteed to stay uniform within a very small area. These small bodies of water were never intentionally added, but are very difficult to remove and were kept in due to lack of time.
